Identity

Agent identity from receipts

An agent's receipt chain IS its identity. No centralized registry. DID-based, ephemeral or persistent, automatically built from action history.

Verification

Tamper-evident by default

Every receipt is Ed25519-signed over JCS-canonicalized JSON. Modify one byte and verification fails. No trust required — only math.

Compliance

EU AI Act ready

Direct mapping to Articles 12, 19, and 26 logging requirements. Export receipts in compliance format. Audit-ready from day one.

Privacy

Hashes only, never data

Receipts contain SHA-256 hashes of inputs and outputs — never the raw data. GDPR crypto-shredding compatible. Privacy by architecture.

Performance

<1ms receipt generation

Signing is fast. Anchoring is async and batched. Zero impact on agent latency. Receipts are tiny JSON — kilobytes, not megabytes.

Universal

Works with everything

Framework-agnostic, model-agnostic, chain-agnostic. Python and TypeScript SDKs. LangChain integration. MCP server. Apache 2.0 licensed.

Complements existing standards

RCPT doesn't replace OAuth, OIDC, or SPIFFE. It adds the missing non-repudiation and audit layer.

Ed25519

RFC 8032 signatures

Fast, compact, deterministic. The same curve used by SSH, Signal, and Solana.

JCS

RFC 8785 canonicalization

Deterministic JSON serialization. Same input always produces the same bytes to sign.

DID

W3C Decentralized Identifiers

Agent identity IS the public key. No registry dependency. Interoperable with OIDC claims.

MCP

Model Context Protocol

Native MCP server. Any MCP-compatible agent can generate and verify receipts as a tool.

NIST

NCCoE agent identity

Submitted to NIST's call for agent identity and authorization solutions.

EU AI

AI Act compliance

Maps to Articles 12, 19, and 26 audit logging requirements. Enforceable August 2026.
